# 视频大师」本机方案外部评审（Claude 原文）

> 存档。可执行步骤见 [视频大师-双规格升级实施计划.md](./视频大师-双规格升级实施计划.md)。

## 1. 方案是否自洽

整体自洽。seek(t) 的确定性、外部 image2pipe、事后感知三件事互不依赖，4K60 只要保持为渲染期参数，就不会动到底座。

【问1】双规格比直接改默认合理。默认改成 4K60 会让 qa、已有夜曲片和 village_teacher 的验收口径同时失效，渲染成本还约 16～20 倍。4K 对知识短片的收益主要在字幕和细线的清晰度，60fps 对慢节奏片子几乎没有收益。所以建议把分辨率和帧率做成两个独立开关，而不是绑成一个「4K60」。这样可以先验 4K30，再加 60。

有几处张力需要先处理：

- 「交付规格」被放进了「作品」里：tokens.canvas.fps 是每片的属性。
- 「storyboard 只是契约」与「节拍契约约束 storyboard」之间，如果没有校验器，约束会退化成口头约定。
- 改 vk.js 会影响所有未来重渲的片子，包括乡村教师。必须有保护手段（S=1 哈希）。
- README 落后于二进制，应先清。

## 2. 真正的卡点

- **规格放错了位置。** 应用 `render.py --scale 2 --fps 60`，注入独立的 `window.VK_RENDER={scale,fps}`，与 tokens 无关。
- **瓶颈在 Chromium 截图和 PNG**，不在 ffmpeg。必须实测 `--jobs 2` vs `--jobs 4`。
- **shadowBlur 不受 setTransform 影响**，包装函数里必须乘 S。
- **并行分段 HEVC 拼接**必须单独验证。
- **色彩标记**：默认档若没写 bt709，记为已知问题不要顺手修；新档必须显式 bt709。
- **8-bit 暗场色带**：HEVC 必给 `-b:v`；10-bit 先别做。

## 3～5

推断需求、最小升级顺序（第 0～6 步）、明确不要再推荐的替代方案：见实施计划。成片超过约 3 分钟或画面未锁定时不要走 4K60；日常迭代永远 1080p30。
