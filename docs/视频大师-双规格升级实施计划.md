# 视频大师 · 双规格升级实施计划

依据 Claude 外部评审纠偏。底座不变：`seek(t)` + `image2pipe` + `vk.js` / `audio.py`。默认仍是 **1080p30 H.264**；4K / 60fps / HEVC 是可选交付档，互不绑死。

## 硬约束

- 规格是「每次交付」，不是「每片」：用 `render.py --scale` / `--fps`，注入独立的 `window.VK_RENDER={scale,fps}`，**不写进** `tokens.json`。
- 分辨率与帧率正交；先验 **4K30**，再加 60。
- `--vt` 与 `--hevc` 正交：`--vt`＝H.264 VT→x264；`--hevc`＝x265；`--vt --hevc`＝HEVC VT→x265；双失败直接报错，禁止静默回退 H.264。
- 预设 `--spec uhd60` ≡ `--scale 2 --fps 60 --hevc --vt`。
- `S=1` 帧哈希必须与升级前一致（保护乡村教师不重渲也能被未来引擎接住）。
- 不换引擎；不重渲 `village_teacher*`；不动仓库目录名。
- 默认档不顺手改 bt709（已知问题）；**新档**显式写 bt709。
- uhd 母版拒绝 `--douyin-pad`。

## 步骤

### 第 0 步 · 文档与基线（不改引擎）

- 改：`README.md`，对齐本机 `bin/ffmpeg` 真实编码器（含 `hevc_videotoolbox` / `libx265` / `libkvazaar`）。
- 验收：`ffmpeg -encoders` 与 README 一致；默认档渲 `capability_demo`，记下 0.5 / 2 / 5 / 9 s 帧哈希、耗时、`qa_final`。
- 不要顺手改：引擎、目录名。

### 第 1 步 · 渲染期 `--scale` / `--fps`

- 改：`engine/vk.js`（逻辑 W/H + `S`，画布 `×S`，每帧 `setTransform(S,…)`）；`engine/render.py`（`--scale {1,2}`、`--fps`、viewport＝逻辑×S 且 DSF=1、注入 `VK_RENDER`）。
- 验收：`S=1` 基线帧逐像素一致；`S=2` 用 `--clip` 渲约 3 秒，输出 3840×2160。
- 不要顺手改：`film.js`、tokens 默认、qa、audio、编码器。

### 第 2 步 · 4K 外观校正（主要动 vk.js；必要处 vk-kit）

- `shadowBlur` / `filter` blur 乘 `S`；颗粒贴图折中（1080 级 + 最近邻放大）并按固定 **30Hz** 轮换；离屏缓冲随 `S`；`setTransform(1,…)` 复位处改为 `S`。
- 验收：4K 帧缩到 1080 与 1080 帧比，辉光外延差几个像素内；`S=1` 哈希仍一致。

### 第 3 步 · `--hevc` + `--spec`

- 改：`render.py` 编码器选择集中成函数；并行分段透传新开关；新档显式 bt709 + HEVC 必给 `-b:v`；必要时 `audio.py` 保 `hvc1` / `faststart`。
- 验收：短片显示 hevc、hvc1、3840×2160、目标 fps、yuv420p；VT 失败落到 x265；concat 无花屏。

### 第 4 步 · qa 分档

- 改：`tools/qa_final.py`：`--tier hd30|uhd60`（默认 hd30）、`--audio-profile synth|bgm`；uhd 拒 `--douyin-pad`。
- 验收：hd30 原样过；跨档互判失败。

### 第 5 步 · 10 秒端到端

- `capability_demo` 走高规格全流程，输出与默认档分文件（如 `final_uhd60_hevc.mp4`），对比 `--jobs 2` / `4`；再重跑默认档确认哈希。
- 不要顺手改：`village_teacher*`。

### 第 6 步（可并行，本轮可后置）

- `beats.json` 契约 + 校验器；不做拆拍器、不做 storyboard↔sfx 联动。

## 明确不做

换引擎 / 默认改 4K60 / 1080 后期放大冒充 4K / 本仓库拆拍 / MusicGen 生产声源 / 恢复 A 鎏金为默认 / 改目录名 / 10-bit·HDR·ProRes。
