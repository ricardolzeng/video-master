# 视频大师 · 全片文案外部评审（给 Claude）

你是外部评审，不要改代码，不要重写引擎。请只评审「全片文字层」是否自洽：底部字幕 + 画面上所有字。

输出用中文，按这个顺序：
1. 卡点是否找对（十行以内）
2. 文字分层表是否够用：采纳 / 改字段 / 砍字段
3. 推断需求：采纳 / 拒绝 / 先别做，每条给理由
4. 最小升级顺序（仍保持 seek(t) + image2pipe）。每步写改哪些文件、如何验收、不要顺手改什么
5. 明确不要再推荐的替代方案

## 最终目标

产品名「视频大师」：本机 Cursor 驱动的无旁白知识短片。观众**同时读两类字**：

- **字幕层**：底部一行中文（C 夜曲还有英文行），由 `SUBS` + `K.subs` 画。
- **画面字层**：主体区、四角、装置上的字——大字钩子、章节标、标注、卡片标题、仪表读数、出处、黑板公式、UI 标签等。它们散落在 `film.js` 的 `fr.text` / 道具函数里，**目前没有统一总表**。

用户当前痛点：成片里「画面上的文案」不符合预期——不只是字幕措辞，也包括屏上大字、左右栏标签、卡片标题、小字标注是否该出现、用什么词、和字幕是否打架。

已有、且本轮不要推翻的底座：
- `seek(t)` + Playwright screenshot + `image2pipe` + `vk.js` / `vk-kit.js` / `audio.py`
- 默认 16:9 · 1920×1080 · 30fps · H.264；可选高规格另案
- 外观默认 C 夜曲；B 寓言仍可用
- 声音：`fr.sfx` → `--events` → `audio.py`
- 成片感知：`watch.py` / `listen.py` / `read_subs.py`（OCR **只对底部字幕**）

## 当前卡点（请评审对不对）

1. **文字契约不完整。** `references/script.md` 只管字幕句长和句式。`storyboard.md` 有时写「屏上是什么」，但不强制列出「屏上写什么字」。画面字在写 `film.js` 时现编，用户预期无法在开渲前锁死。
2. **两层字容易重复或打架。** 例：底部字幕说「左边：五万光年外…」，屏上又写「左 · 银河」「人造太阳 × n」；或钩子大字「止痛药都吃不起」与字幕几乎同义叠读。参考片的原则是：字幕讲句，画面字报数据 / 命名 / 定位，不复述整句。
3. **质检只盖字幕层。** `read_subs.py` 用 PaddleOCR 对 `SUBS`。画面字（y 多在 80–840）不进核对；改坏标注也不会被 report。
4. **乡村教师加厚版是反面样板。** `films/village_teacher_rich/film.js` 里画面字极多（分栏标签、卡片标题、三大定律、审判 UI 英文、孩子名等），全部硬编码在绘制函数里，没有 `ON_SCREEN` 表，也没有和用户确认过的文字总表。
5. **技能边界模糊。** `vibe-knowledge-film` 把讲解设计、外观、引擎、文案挤在一起。用户要单独的「脚本 skill」：开拍前锁文字，开渲后按总表验收——不管画面道具怎么画。

## 当前文字是怎么进画面的（事实，请按此评）

| 层 | 来源 | 画法 | 现在有没有表 |
|---|---|---|---|
| 底部字幕 | `SUBS[]`：`{a,b,zh,en?}`，`{词}`/`{!词}` 染色 | `K.subs(fr,t,SUBS,'night'\|'flat')` | 有 |
| 章节标 | `MARKS[]`：`{t,no,zh,en}` | `K.chapterMark` | 有数组，无文案评审 |
| 片名卡 | `titleNight` / `titleGilt` 的 zh/sub/en/tag | kit 函数 | 散在调用处 |
| 钩子大字 / 命名大字 | `fr.text` / `dustText` 硬编码 | 各镜函数 | 无 |
| 装置标注 | `fr.text` 贴主体 | 各镜函数 | 无 |
| 卡片 / UI / 黑板 | `flashCard`、考试面板、定律行等 | 各镜函数 | 无 |
| A 年份 HUD / 出处 | `hudYear` chapters | kit（菜单已不默认 A） | 有结构 |

生产流程现状：立题 →（可选）字幕稿 → 分镜 → `new_film.py` → 写 `film.js`（字幕 + 画面字一起写）→ 静帧 → 全片 → `audio` → `qa` / `read_subs`。

**缺的一步：** 在写任何 `fr.text` 之前，交付并经用户确认一份「文字总表」，覆盖字幕 + 画面字。

## 拟议的文字总表（尚未拍板，请评审字段）

每行一类上屏字，建议列：

```
时刻  层(sub|hook|mark|label|card|hud|title|ui)  位置  中文  英文?  作用(叙事|命名|报数|定位|出处)  与字幕关系(互补|可删|禁止复述)
```

过关：遮住「屏上道具描述」，只读总表里的字，能读懂这一段在讲什么；同一秒内字幕与画面字不同义叠读。

## 我没有明说、但必须一并评审的需求

1. 脚本 skill 只管「字写什么、何时上屏、和字幕什么关系」；不重写渲染引擎，不替代 `visualization.md` 的找形象。
2. 画面字默认短：标注 ≤ 8 字，钩子大字 ≤ 10 字，卡片标题 ≤ 6 字；更长的优先进字幕，不要两层都长。
3. C 夜曲画面字尽量中文；英文只留给章节标 en、等宽 UI 气质行、必须出现的符号（F=ma、bit/s）。不要中英各写一整句同一意思。
4. `read_subs.py` 短期仍只对字幕；若加画面字核对，先做「从 film.js 抽出字符串清单 vs 文字总表」的静态 diff，不要一上来全屏 OCR。
5. 不重渲已归档的 `village_teacher*` 成片；新 skill 用 `capability_demo` 或新工程验收。
6. 不要建议用 Remotion / 口播 / 后期烧字幕替换现有字幕层。
7. 产品名「视频大师」与目录「视频生成自动化」分开；不要为改名动路径。
8. MusicGen / 版权配乐问题本轮不讨论。
